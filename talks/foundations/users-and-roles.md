# Superdev - Foundations: Users and Roles

- **Status:** Active

## Users and roles

| Role | Who | Primary goals |
|---|---|---|
| Non-technical founder | A founder building a product who does not have a software engineering background | Describe what they want built in plain language and have Superdev turn it into a working product without needing to understand architecture, databases, APIs, or infrastructure |
| Product owner | A person responsible for defining and prioritizing what a product should do | Shape and track product scope, features, and decisions through Superdev without needing deep technical knowledge |
| Developer | A technical practitioner building the product | Use Superdev to keep implementation aligned with the product model, tasks, and documentation while writing code |
| Engineering lead | A person responsible for the technical direction and quality of a project | Oversee architecture decisions, review progress, and ensure the product model and database remain the authoritative source of truth |
| Designer | A person responsible for the product's user experience and interface | Ensure the product's design and user-facing behavior are captured and tracked accurately through Superdev |
| AI-assisted development team | A team that builds products primarily by directing coding agents rather than writing all code by hand | Coordinate human and agent contributors around one shared, human-readable product model |
| Solo developer using coding agents | An individual developer who relies on coding agents to build most of a product | Get reliable, low-effort tracking and guidance from Superdev while working largely through an agent rather than manually |
| Claude Code | A coding agent environment that can act as a Superdev agent user | Read current project state, work only on mapped tasks, update state and documentation as it implements, and hand off cleanly without exceeding approved scope |
| Codex | A coding agent environment that can act as a Superdev agent user | Read current project state, work only on mapped tasks, update state and documentation as it implements, and hand off cleanly without exceeding approved scope |
| skills.sh-compatible agent | Any coding agent that supports the skills.sh interface and can act as a Superdev agent user | Read current project state, work only on mapped tasks, update state and documentation as it implements, and hand off cleanly without exceeding approved scope |
| Future supported coding-agent environment | A coding agent environment not yet named that Superdev will support as an agent user | Operate under the same rules as other agent users: work only on mapped tasks, record evidence and blockers, and never claim completion without proof |
